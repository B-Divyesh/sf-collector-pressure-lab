Route 01 Collector pressure test

Find your Collector's pressure threshold

For OpenTelemetry operators testing when a local Collector queues, slows, or drops telemetry.

Try it with sample data Loads the bundled sample and shows the result. Install the CLI
  • Free to use.
  • Works offline after the first visit.
  • Runs against loopback by default.
Test evidence, not a capacity guarantee. Use an isolated Collector and repeat with production-shaped samples before changing limits.

How the pressure test works

Test one sample at increasing rates

  1. 01

    Read Collector config values

    Read queue size, consumer count, and batch config values. Templated values remain unknown.

  2. 02

    Replay bounded requests

    Replay JSON requests at increasing rates within fixed safety limits.

  3. 03

    Classify the first failure

    Classify each run as stable, backpressure, or drops.

Collector CLI

Test your local Collector from the terminal

The Rust binary sends a bounded sample to your local OTLP/HTTP receiver. It reads Collector self-metrics when available.

Human output describes the result. Use --json in scripts.

  • ✓ One Rust binary
  • ✓ Loopback endpoint guard by default
  • ✓ Never edits the Collector config

What the CLI can and cannot measure

Know what the result means

Measurements

See response latency, throughput, non-success responses, and available Collector queue or failure metrics for each rate.

Suggested next tests

Test queue size, consumers, batches, downstream latency, or a narrower range of request rates.

Limits

The CLI generates bounded traffic and never edits your Collector config. Results do not guarantee production capacity.
